# TipCheck QA Status & Issue Tracking

This document tracks all discovered defects, reproduction details, root cause analyses, applied code remediations, retests, and current resolution statuses across the TipCheck system.

| ID | Component | Problem | Severity | Root Cause | Fix | Retest | Status |
| --- | --------- | ------- | -------- | ---------- | --- | ------ | ------ |
| QA-001 | Test Infra | `pytest` collection failure (`ModuleNotFoundError: No module named 'backend'`) | High | Workspace root was missing from `PYTHONPATH` during standalone test execution | Added `pytest.ini` configuring `pythonpath = .` and `testpaths = tests` | `pytest` passes all 29 tests cleanly | **FIXED** |
| QA-002 | API | Missing mandated `/ocr` endpoint | High | Endpoint `/ocr` specified in specification Section 10 was absent (returned 404) | Implemented `@app.post("/ocr")` in `backend/main.py` with validation and honest error reporting | Added `test_ocr_endpoint_unconfigured_provider` unit test | **FIXED** |
| QA-003 | API | Missing mandated `/analyze` unified endpoint | Medium | Only `/analyze/text` and `/analyze/image` were implemented; `/analyze` returned 404 | Implemented `@app.post("/analyze")` alias in `backend/main.py` | Added `test_analyze_unified_endpoint` in `tests/test_api.py` | **FIXED** |
| QA-004 | OCR Tool | EXIF stripping crashes on CMYK JPEG images with `OSError: cannot write mode CMYK as PNG` | High | PIL `clean_img = Image.new(img.mode)` attempted to save CMYK mode into PNG format | Convert image mode cleanly to `"RGB"` or `"RGBA"` before saving clean PNG buffer | Tested with synthetic CMYK JPEG; processed cleanly without exceptions | **FIXED** |
| QA-005 | Extraction | Urgency language regex missed `"within the next 10 minutes"`, `"expires in"`, `"immediate"`, etc. | High | Incomplete keyword list in `agents/extraction_agent.py` | Expanded `urgency_keywords` regexes to capture time-bound intervals, immediacy, and Hinglish urgency | Tested `"Invest within the next 10 minutes."` -> Triggers `PSY-01` | **FIXED** |
| QA-006 | Extraction | Payment requests missed `"Send ₹25,000 to activate your account."` | High | Regex prefix only looked for `pay/fee/charges` and failed on `send/deposit/₹` syntax | Added `send`, `deposit`, `₹` currency symbols, and activation terms to payment regex | Tested `"Send ₹25,000 to activate your account."` -> Triggers `PAY-01` | **FIXED** |
| QA-007 | Extraction | Scarcity missed `"Only 5 slots left!"` | Medium | Exclusivity patterns required word `limited` or `vip` | Expanded regexes to match `\d+ slots left` and `only \d+ slots/seats/spots` | Tested combined multi-signal input -> Triggers `PSY-02` | **FIXED** |
| QA-008 | Risk Engine | Missing Registration rule was absent when an advisor claimed tips without SEBI Reg | High | When entity name was claimed without reg number, no regulatory warning flag fired | Added rule `REG-04` ("Missing Registration Number", score 20) in `rules.yaml` and `backend/services/rule_engine.py` | Tested `"Market advice from Sharma Financial Services"` -> Triggers `REG-04` (Score 20, `NEEDS_VERIFICATION`) | **FIXED** |
| QA-009 | Risk Engine | Combined realistic signals in Section 7 under-classified as `NEEDS_VERIFICATION` | High | Because urgency, payment, and scarcity patterns failed to extract, cumulative score was only 40 | Fixed extraction regexes across all signals; cumulative score now reaches 80 | Retested multi-signal prompt -> Triggers FIN-01, FIN-02, PSY-01, PSY-02, PAY-01 (`HIGH_RISK_INDICATORS`) | **FIXED** |
| QA-010 | Frontend | Misleading low-concern summary claimed "registration matches active official SEBI records" for un-registered messages | Medium | Hardcoded string in `VerdictView.tsx` assumed all low-concern messages had registrations | Dynamically adjusted summary based on whether a registration number was claimed | Verified rendering for both registered and general messages | **FIXED** |
| QA-011 | Frontend | API error details swallowed into generic connection failure messages | Medium | `App.tsx` did not parse response JSON body on HTTP errors | Updated `handleAnalyzeText` and `handleAnalyzeImage` to parse and display `res.json().detail` | Verified user gets clear, actionable error messages | **FIXED** |
| QA-012 | UI / Compliance | Transparent labeling of synthetic demo registry records | Medium | Regulatory references in Navbar and Modal headers could be mistaken for live SEBI connection | Explicitly labeled as **Demo / Synthetic SEBI Registry Snapshot** across Navbar, Registry Modal, and Verdicts | Verified UI clearly reflects synthetic demo data per Section 13 | **FIXED** |
| QA-013 | Frontend | Unused catch parameter warnings in `App.tsx` | Low | Catch block declared `catch (_)` triggering oxlint warnings | Replaced with modern parameterless `catch {}` | `npm run lint` passes with 0 warnings and 0 errors | **FIXED** |
| QA-014 | OCR Tool | Local OCR returned 422 without external OCR provider installed | High | Neither AWS Textract nor Tesseract was installed locally, causing local image OCR to fail | Implemented Windows Native OCR (`tools/win_ocr.ps1` via `Windows.Media.Ocr.OcrEngine` WinRT API) with graceful fallback, enabling local screenshot text extraction | Tested with text screenshots: returns 200 with extracted text; blank/illegible images report clear honest error | **FIXED** |
| QA-015 | Frontend | State synchronization warning in `<ExtractionConfirmation>` | Medium | Direct `setState` inside `useEffect` triggered React Compiler / oxlint warnings and risk of stale state leakage | Moved to prop-based keying (`key={claim.claim_id}`) in `VerdictView.tsx` ensuring automatic fresh component initialization on analysis switch | Tested switching between cases: zero state leakage, 0 lint warnings | **FIXED** |
| QA-016 | Frontend | Double submission vulnerability on rapid clicking | Medium | Lack of lock guard allowed concurrent duplicate analysis requests | Added `if (isProcessing) return;` guard in `Analyzer.tsx` and `App.tsx` and disabled button while processing | Verified rapid clicking cannot trigger duplicate API calls or race conditions | **FIXED** |
| QA-017 | Frontend | Missing full state reset button | Medium | Users had to manually backspace or select all text to clear input; verdict remained displayed | Added "Clear" button next to submit in `Analyzer.tsx` triggering `handleClearAll()` which resets text and clears active verdict | Tested via browser: resets character counter to 0, clears textarea and verdict display | **FIXED** |
| QA-018 | Frontend | Benchmark cases truncated to only 3 cases in UI | Low | Only cases A, B, C were exposed in UI, hiding cases D through G from direct browser testing | Added toggle button "Show all 7 benchmark cases" / "Show 3 featured" in `Analyzer.tsx` | All 7 benchmark cases (A through G) verified clickable and functional in UI | **FIXED** |
